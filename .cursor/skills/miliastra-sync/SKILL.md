# 确认后同步仓库和记忆

时机到了就做。不要问「要不要我提交」。用户还没确认文件无误时，只展示文件并停下。

## 什么时候进入

- 用户表示某张节点图做完了，或把做好的资产文件交出来
- 用户说资产没问题、确认无误、可以上传
- 用户建了文件夹存放某个游戏的全部资产，并且最终给出的文件已经确认无误

同一条消息里既给了文件又确认无误：先在回复里列出文件，然后直接做「入库」，不要再等一轮。

## 永不入库

这些路径不要 `git add`，即使用户确认了也不要推：

- `门限夺宝/`
- `门线夺宝/`
- `文档/限时夺宝-时间门/`
- `memory/local/`
- `**/node_modules/`
- `.env`、凭据、`*.log`

只允许入库的常见资产，是用户点名的那两份（已在仓库根目录）：

- `常用复合节点大全v1.7(补充包同步更新中).gia`
- `数据结构：队列-二维数组-栈.gia`

私人玩法若混在待上传列表里：跳过那些路径，告诉用户它们留在本机，其余确认过的文件继续入库。

## 1. 展示文件

列出将要提交的路径。GIA 只写文件名和路径，不要把二进制贴进对话。

用户还没确认：列表写完就停，请他确认这些文件是否无误。不要 pull，不要 push。

完成：用户看到的列表和接下来会 `git add` 的路径一致。

## 2. 入库

确认之后立刻执行，路径用明确的 `git add`，不要 `git add -A`。

1. `git status --short`，核对没有夹带「永不入库」的路径
2. `git pull origin main`（当前分支不是 main 就拉当前分支）。远程还没有提交时跳过 pull
3. 出现冲突时按 `memory/MERGE.md` 合并：记忆条目两边都留，不要丢掉对方写过的经验
4. 只暂存本次确认过的项目文档、资产和已解决的记忆文件
5. 提交并 `git push`。不要 force push

提交说明写为什么要共享这批文件（哪张节点图或哪套资产可以给协作者用了）。

完成：`git status` 显示与远程同步，且 `git ls-files` 里没有门限夺宝、门线夺宝路径。

## 3. 写记忆并再同步一次

入库成功后立刻做，不要等用户说「记一下」。

新建 `memory/lessons/YYYY-MM-DD-<主题>.md`（日期用当天，主题用这次做完的原件或节点图）。写四段：

- 做了什么（原件、节点图、完成到哪）
- 遇到的问题
- 怎么解决
- 协作者下次可以直接用的结论

只属于未入库私人玩法、换一局就没用的关卡细节，写进 `memory/local/`，不要提交。编辑器手法、节点真名、ID 空号、计时器控件这类下一局还用得上的，写进 `memory/lessons/`。

在 `memory-graph.md` 的 Lessons 追加一行，指向这篇 lesson，不要把整篇再抄一遍。

然后再次 pull、按 `memory/MERGE.md` 合并、只暂存这篇 lesson 和 `memory-graph.md`、提交、push。

完成：远程上能看到这篇 lesson，其他协作者 pull 之后能读到这次做了什么、卡在哪、怎么解决的。
