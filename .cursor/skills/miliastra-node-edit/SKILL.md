# 千星沙箱节点图编辑说明

这局若已经有 `projects/<slug>/`：先按 `.cursor/skills/miliastra-project/SKILL.md` 读完 BRIEF、原件清单和这张节点图文档，再用文档或导出里的搜索 ID。两处都没有的 ID 写「文档未记录」，不要编。

## 强制要素（含搜索 ID）

指导用户编辑节点图时，**每一条改动**必须同时给出，缺一不可：

| # | 要素 | 含义 | 示例 |
|---|---|---|---|
| 1 | **元件名称** | 预制体/元件名，并写明节点图 | `元件「刷新点」/ 节点图「尝试刷新」` |
| 2 | **节点卡名称** | 编辑器中文节点名（以编辑器能搜到的为准） | `启动定时器` |
| 3 | **搜索 ID** | 节点卡在图内的 index（非坐标） | `ID 23` |
| 4 | **字段名** | 该节点上的参数/引脚中文名 | `定时器名称` |
| 5 | **参数** | 手填值，或接线来源 | `准备` 或 `← 实体创建时(ID 1) · 事件源实体` |

同名节点卡靠 **搜索 ID** 区分。解析 `.gia` 时 `node.index` 即此 ID（debugPrint 写作 `Index: N`）。

### 新建节点卡的 ID 推算（强制）

编辑器分配规则（已用多轮导出验证）：

1. **先填空号**：曾删除/未使用的 ID（如删掉 8、14）会优先分给下一批新建卡。
2. **空号用尽后**再从当前**最高 ID +1** 递增。
3. 同一批连续新建：按创建顺序依次吃掉「最小空号 → 次小空号 → … → 最高+1 → 最高+2…」。

推算时必须：

- 先列出该图**已占用 ID**与**空号**（从最近一次导出 / 审计 log 读 `Index`）。
- 按说明中的**创建顺序**，给第 1 张新建卡分配**最小空号**；没有空号才用 `最高+1`。
- 说明里**直接写死推算 ID**，勿让用户事后回报。
- **导出 GIA 与推算冲突时，以导出为准**，并修正后续引用。

示例（已占用 1–7、9–13、15–47，空号含 14；最高 47）：

```text
（空号优先：14；然后 48…）
1. 获取场上指定元件ID的实体 → ID 14
2. 获取列表对应值 → ID 48
```

勿再假设「新建一定 = 最高+1、+2」（无空号时才成立）。

### 输出模板

```text
元件「<元件名>」/ 节点图「<节点图名>」
节点卡「<节点卡中文名>」(ID <n>)
  - 字段「<字段名>」：<手填值 或 ← 来源节点卡(ID x) · 来源字段>
执行流（若涉及）：
  - 逻辑入：← <上游节点卡>(ID a)【<出脚>】
  - 逻辑出：→ <下游节点卡>(ID b)（无下游写：不接）
```

涉及「设置自定义变量」时，必须写清：目标实体、变量名、变量值、是否触发事件（及类型）。

### 完成标准

- 同名多卡必须带 ID；新建卡也要带推算 ID。
- 接线写满「来源节点卡(ID) · 来源字段」。
- 执行流写明入/出接到哪张卡的哪个脚；终端写「不接」。
- 布尔「是/否」；**只写需要改的**；勿把节点卡叫成节点图。
- **节点中文名以用户编辑器搜索结果为准**；知识库/工具链别名可能搜不到。

## 易错节点中文名（编辑器实测）

| 勿写（知识库/旧称） | 应写（编辑器） | 备注 |
|---|---|---|
| 列表迭代 | **列表迭代循环** | 脚名见下 |
| 修改界面布局内界面控件状态 | **设置界面控件(组)状态** | 显隐用这个 |
| （臆造「结束」「迭代」出脚） | **循环完成** / **循环体** | 见下表 |

**列表迭代循环** 脚名（以编辑器为准）：

| 方向 | 编辑器名称 | 库/解码常见名 |
|---|---|---|
| 入 | 开始 | Start |
| 入 | 跳出循环 | Break |
| 入（数据） | 迭代列表 | list |
| 出 | 循环体 | Iteration |
| 出 | 循环完成 | End |
| 出（数据） | 迭代值 | item |

**界面控件组**分类常见节点：播放界面动效控件、更新消息队列、激活控件组库内界面控件组、切换当前界面布局、设置界面控件(组)状态、移除控件组库内界面控件组。

## 全局计时器 + 计时器控件（易踩坑）

1. 控件绑定的全局计时器**未启动**时，界面固定显示 `00:00`（官方行为）。
2. 要「开局就显示满时长、准备阶段不往下走」：`启动全局计时器` → `暂停全局计时器`；阶段切换时用 `恢复全局计时器`，不要再次 `启动`。
3. **多个计时器控件**时：先怀疑**可见性叠加**，再怀疑计时逻辑。准备走完后若准备控件未隐藏，会盖住/叠在关门控件上；关掉关门「初始可见」后屏幕上的 `00:00` 可能是准备控件，不是关门。
4. 推荐：准备控件初始可见开、关门控件初始可见关；开门时对每名玩家 `设置界面控件(组)状态`：准备→隐藏，关门→开启。
5. 显示状态解码参考：1901=开启，1902=隐藏。

拿不准节点名时：让用户从编辑器分类列出可见节点，或对照同图已有卡（如已有「列表迭代循环」ID 8）。

查节点含义可配合 `文档/skills/miliastra-knowledge`；解析本地 `.gia` 用 `tools/` 下 Wu-Yijun 工具链。**不要**把第三方重打包整包 GIA 当可导入交付物。
