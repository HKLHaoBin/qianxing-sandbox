# 从玩法描述到原件清单

用户说出想做什么之后，本技能负责把整局拆成可分工的项目文档。协作者不翻 GitHub，他们的 AI 读这些文件。

先读 `memory-graph.md`、`memory/lessons/`，以及存在的 `memory/local/`。再看根目录这两份可复用资产，能导入就写进 BRIEF，不要先发明一套新的队列或复合节点：

- `常用复合节点大全v1.7(补充包同步更新中).gia`
- `数据结构：队列-二维数组-栈.gia`

玩法里若有屏幕 UI / 2D 表现（手牌扇形、自定义 HUD、界面动画、点选叠层等），先读 `.cursor/skills/miliastra-lua/SKILL.md`：**这类表现优先用客户端 Lua**，权威规则仍用服务端节点图。原件清单里把「客户端控件/脚本」与物件元件分开列，不要把扇形手牌默认拆成一排 3D 物件节点图。

## 步骤

### 1. 建项目目录

用玩法名做 slug（空格改 `-`）。目录是 `projects/<slug>/`。

把 `projects/_template/` 里的结构用作版式。正式原件写好后，删掉 `示例元件`。

完成：`projects/<slug>/` 已存在。

### 2. 写 BRIEF

`projects/<slug>/BRIEF.md` 只用用户已经说出的目标：谁在玩、怎样算赢、一轮里发生什么。假设单独标成「待确认」，不要写成已定事实。

完成：文件里的目标能对上用户原话，待确认项有标记。

### 3. 先列全原件，再写伪代码

`projects/<slug>/原件清单.md` 先于任何一份伪代码写完。每一行一个原件：

| 原件 | 职责（一句话） | 节点图 | 状态 |
|---|---|---|---|

节点图列全该原件下的每一张图，用中文顿号分开。玩法描述里还没点名、但局能跑起来所缺的原件也要列上，并在职责里注明这是补全。

UI / 2D 项：节点图列可写「客户端脚本」或具体脚本职责；状态栏同样用制作中/完成。需要扇形手牌等表现时，在职责里写明「优先 Lua」，并点名对应的客户端控件模板（若已知）。

完成：回复里看得到完整表格，且和文件一致。此时还没有只写了其中一个原件就停下来。UI 项不会被误标成必须实体节点图。

### 4. 逐个写伪代码和节点图文档

按清单顺序，给每个原件写：

- `projects/<slug>/原件/<原件名>/伪代码.md` — 玩家可见的行为和数据变化。这里不写搜索 ID。
- `projects/<slug>/原件/<原件名>/节点图/<图名>.md` — 每张节点图一份。写明这张图在整局里的位置、对应伪代码的哪一段、制作步骤。还没有导出时，搜索 ID 写「待导出」。

一份写完再写下一份，直到清单上的原件都有文件。

完成：清单里每个原件、每张节点图都有对应文件。缺一个，这一步就没完。

### 5. 写分工

`projects/<slug>/分工.md` 把每张节点图各列一行：原件、节点图、负责人、状态。用户没指定负责人时，负责人留空，状态写「未认领」。

完成：清单里的每张节点图在分工里恰好出现一次。

### 6. 交给用户的说法

回复先给原件总表，再给分工表。告诉用户把活分出去时，让对方直接对 AI 说：

`我需要元件「<原件名>」的节点图信息。`

不要让对方去仓库里翻 markdown。

这一步只产生文档。上传要等用户确认资产无误，那时改走 `miliastra-sync`。

完成：用户能从回复里把任意一行分工原句转给协作者。
