# 格式层边界

对齐上游 `qianxing-format-docs` 的诚实声明与本协作栈习惯。

## 定位

- **观察性知识**：本地文件格式、编辑器重保存/校验行为、测量数据、方法论。
- **第三方研究**：非官方、非米哈游授权；结论有证据分级，会随编辑器版本漂移。

## 不要用本技能做的事

- 不把格式层结论写成「官方保证」或替代 `miliastra-knowledge` 的玩法配置说明。
- 不在本协作栈中索取或补写：网络协议线级细节、进程内注入/修改配方、绕过官方通道的发布手段。
- 不把对方 `src/qxfmt` 或示例产出直接当成已在真机/官方编辑器验证通过的交付物；需真人验收。
- 不把格式文档里的节点别名、旧称直接写进五要素改图说明；改图仍遵守 `miliastra-node-edit`（编辑器可搜中文名 + 搜索 ID）。

## 与官方知识库分工

| 问题类型 | 权威顺序 |
|----------|----------|
| 「这个节点干什么 / 系统怎么配」 | 官方知识库 → 编辑器 |
| 「这个字段在文件里怎么落 / 连线是否兼容」 | 格式层文档（注明篇目）→ 必要时真机重保存对照 |
| 「Lua 控件怎么写」 | 本仓 Lua 档案 → 模拟器 → 真机 |

## 引用要求

- 回答标注读过的 `manuals/…` 或 `docs/…` 路径。
- 保留上游证据标记（若原文有 [A]/[J]/[P]/[C]）。
- 版本敏感结论（类名/混淆名/行为定律）写明绑定版本或标注「需按对方 06 篇方法重验证」。
